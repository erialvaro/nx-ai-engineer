# SEO & AI Discoverability — Engineering Pack

The knowledge standard for making web apps/sites **truly discoverable** — by
classic search (Google/Bing) **and** by AI answer engines (Google AI Overviews,
ChatGPT/Claude/Perplexity search). It feeds the **`seo` agent** (and frontend/docs)
via the Engineering Contract: the agent executes, this pack holds the standard.

## What it covers
- **[policies.md](policies.md)** — non-negotiable rules (indexability, canonicals,
  rendering, titles, structured data, CWV, AI policy).
- **[checklists.md](checklists.md)** — the pre-launch / per-page SEO checklist.
- **[patterns.md](patterns.md)** / **[anti-patterns.md](anti-patterns.md)** — do / never-do.
- **[performance.md](performance.md)** — Core Web Vitals (LCP/INP/CLS) engineering.
- **[structured-data.md](structured-data.md)** — schema.org JSON-LD recipes.
- **[ai-discoverability.md](ai-discoverability.md)** — llms.txt, GEO, E-E-A-T,
  AI-crawler policy.
- **[architecture.md](architecture.md)** — rendering strategy, URL/site structure,
  i18n, redirects.
- **[context.md](context.md)** — the compact brief injected into the agent.

## The five pillars
1. **Crawlable** — bots can fetch every important URL (nothing important blocked).
2. **Indexable** — each page states clearly whether/how to index (robots, canonical).
3. **Relevant** — titles, headings, content and internal links match intent.
4. **Fast & stable** — Core Web Vitals pass on real devices.
5. **Understandable to machines** — structured data + clean SSR HTML + llms.txt,
   so both Google and AI engines can parse and **cite** the content.

Packs are **knowledge only** — no code, no execution.
